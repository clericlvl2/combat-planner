# ADR-006 — Drag-reorder: svelte-dnd-action

Status: **Accepted** (2026-06-28).

**Decision.** Implement manual combats-list reordering with `svelte-dnd-action`.

**Rationale.** The de-facto Svelte drag library: pointer + **touch** + keyboard support, accessible, FLIP animations. Touch-first is mandatory (phone-first app). On drop, the new order updates `listOrder` and persists via the store → Dexie: dragging to reorder persists the order.

**Alternatives.** Native HTML5 DnD (poor/inconsistent on touch, weaker a11y — rejected for a mobile-first tool).

**Consequences.** Reorder is a store transition like any other; order survives reload.

**Exemption (2026-07-28).** `use:dragHandleZone` (`CombatList.svelte`) and `use:dragHandle`
(`CombatRow.svelte`) are a deliberate carve-out from the app's no-`use:`-directive convention —
they're the only API `svelte-dnd-action` ships, and depend on the library's own `update`
lifecycle in a way an attachment cannot express without tearing down mid-drag. A future sweep for
stray `use:` directives should leave these two alone.
